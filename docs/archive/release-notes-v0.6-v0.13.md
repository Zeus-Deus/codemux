## Notes

Shipped in `v0.13.2`: **a chat-reliability + clone-progress cleanup batch.** (1) **"Send now" steering for queued follow-ups** (PR #162) — the greyed queued bubble gains a hover-reveal "Send now" that promotes a queued message into the live turn instead of waiting for it to settle; the fix also keeps the Claude session alive across an interrupt so a send-now dispatches onto a live query rather than a dead child, and drains a JSON-RPC child's stdout to EOF before failing pending requests. See `docs/features/agent-chat.md` § "Send now (steer)". (2) **Git-clone stall detection** (PR #161) — the new-workspace `git clone` replaced its absolute 120s cap with `--progress` stall detection (fails only after 120s of *no* progress) plus a live `git-clone-progress` event, so legitimate slow clones no longer get killed. See `docs/features/workspace-creation.md`. (3) **SSH-bootstrap truncated-binary guard** (PR #157) — the remote-host bootstrap now refuses to install a 0-byte / truncated `codemux-remote`. (4) **OpenCode `serve` respawn** — `ensure_running` respawns a dead `opencode serve` instead of failing. (5) Two subagent/working-indicator fixes (PRs #158, #159, issue #155) — stale running subagents are settled in the transcript layer, and the working indicator survives the empty-first-delta gap. (6) **Idle scrollback serialize off the workspace-switch path** (PR #152) — terminal scrollback serialization moved off the hot switch path.

Shipped in `v0.13.2`: **dead-run detection & interrupted turns** (issue #154). A run that dies without a terminal event (sidecar killed by laptop sleep, a crash, a provider usage-limit cutoff) previously left every "working" indicator live forever and forced the user to notice and manually type "continue". Three parts, all additive: **(1) synthetic child-exit turn event** — the Claude + Codex child-exit watchdogs (`claude/session.rs`, `codex/session.rs`) and OpenCode's SSE reconnect-budget give-up path (`opencode/sse.rs`) now emit a synthetic `TurnCompleted { status: Error { subtype: "child_exited" } }` for the in-flight turn (recovered before it is cleared) BEFORE the terminal `SessionStateChanged::Error`, via the shared pure helper `child_exit_events` (`agent_provider/events.rs`); all three providers also flag the dead session (`is_dead()` → provider `has_session` reports absent) and their `start_session` evicts-and-replaces the corpse, so the next send auto-resumes through `ensure_live_session` instead of routing to a dead child — OpenCode readopting its persisted server-side session id (validated, fresh-session fallback) so the rebuilt session keeps its conversation context. Because `turn_completed` persists, hydrate replays a settled turn. **(2) stall watchdog** — a new Tauri-managed `RunActivityTracker` (`commands/agent_chat.rs`, mirrors `SubagentTracker`) stamps a wall-clock `last_event` per thread in `forward_event` via the pure `activity_update` (mid-turn events stamp, approval-waits pause the clock, turn/session settlement removes the entry); a 30s sweep task (`spawn_stall_watchdog`, spawned after `spawn_event_bridge`) emits a new additive `ProviderRuntimeEvent::RunStalled { thread_id, silent_for_secs }` for any thread mid-turn and silent past the 600s `STALL_THRESHOLD` (wall clock on purpose so a sleep window counts as silence). `RunStalled` is transient — never persisted, leaves the sidebar dot untouched (`map_event_to_pane_status` → `None`), and the reducer clears it on the next real activity; it renders as an amber "No activity for Nm — the agent may have stopped." tail notice. **(3) interrupted turn + Continue affordance** — a new `interrupted` `ChatThreadState` flag, computed at hydrate (`lastTurnUnsettled`: last persisted user turn has no later `turn_completed`) and live on a `child_exited` turn error (or a `session_state_changed{error}` while streaming), drives a "Run interrupted" tail divider and a one-click amber "Continue run" chip in the composer strip that sends the fixed text "Continue" through the normal send path (auto-resume included); it clears on the next running/dispatched/content event or user send. All UI uses design tokens only (`text-warning`/`bg-warning`). Verified with `cargo test` (new pure-fn tracker/stall-selection tests, serde round-trip + child-exit ordering in `events.rs`, strengthened Claude/Codex watchdog ordering integration tests, OpenCode give-up unit tests), `npm run check`, and `npm run test` (new reducer + hydrate cases). See `docs/features/agent-chat.md` § "Dead-run detection & interrupted turns".

Shipped in `v0.13.2`: **transcript scroll perf on Linux WebKitGTK** (issue #129). Three frontend-only fixes to `MessageList.tsx` + helpers: (1) the viewport edge-fade `mask-image` (`WS_FADE_STYLE`) is now gated OFF on Linux WebKitGTK — where `src-tauri/src/lib.rs` forces non-composited (CPU) mode, so the mask forced a full-viewport CPU re-rasterization per scroll frame — and kept on every composited platform (macOS/Windows/dev-mock Chromium, byte-identical); the decision is a pure cached helper (`src/components/chat/transcript-fade.ts`, `decideTranscriptFade`) honoring a `localStorage["codemux:transcript-fade"]="on"|"off"` override, with `isLinuxWebKitGtk` extracted to shared `src/lib/webkit.ts` (re-exported from `webgl-renderer-probe.ts`). (2) `reuseTranscriptSlots` (`transcript-slots.ts`) preserves an untouched slot's object identity across the per-token rebuild, and the row is split into a memoized whole-row wrapper (`SlotRowMemo`) over the existing `ItemRowMemo`/`ActivityRowMemo` leaves, so a streaming token re-renders exactly one wrapper + one leaf instead of all *n* wrappers. (3) A one-shot `content-visibility` support `console.warn` (suppressed under vitest). Frontend + docs only; no Rust change. Verified with `npm run check` + full `npm run test` (new `transcript-fade.test.ts`, 4 `reuseTranscriptSlots` cases in `transcript-slots.test.ts`, a wrapper-render count case in `MessageList.virtualization.test.tsx`). Shipped in `v0.13.2`: **structural sharing in `setAppState` + `React.memo` on the pane tree** (PR #150, issue #127) — the whole active pane tree used to reconcile on every backend tick (the Rust side re-emits the full `AppStateSnapshot` up to ~60×/sec under agent streaming; every emit gave every workspace/surface/pane a fresh ref). `setAppState` now runs `shareStructural(prev, next)` (`src/lib/structural-share.ts`), a single O(n) reconciliation walk that reuses the previous snapshot's refs for every deep-equal subtree — a no-op tick returns the previous top-level ref (zero zustand fan-out), and a change to one workspace leaves every other workspace/surface/pane-subtree identity intact, so `useActiveWorkspace()`/`useActiveSurface()` are stable across no-op ticks with no call-site changes (the `WeakMap`-cached `buildSessionWorkspaceIndex` stays correct: reused ref ⇒ unchanged content). Deliberately NOT the removed full-snapshot `JSON.stringify` dedup (reverted for freezes): no string allocation, per-branch early exits, at most one walk per 16ms debounce window. On top of the stable refs, `PaneContainer`, `PaneNode` (recursion resolves to the memoized component; also fixes a latent rules-of-hooks bug — `useAppStore`/`useFeatureFlags` were called after the split early-return), `TerminalPane` + `BrowserPane` (export-only wrappers, xterm lifecycle untouched), `TabBar`, `PresetBar`, and `RightPanel` are `React.memo`-wrapped. Frontend only; nothing on the keystroke echo path. Verified with `npm run verify` (165 files / 2383 tests) incl. 18 new `structural-share.test.ts` cases and the 5-case `pane-tree-rerender.test.tsx` Profiler suite proving zero pane-tree commits on deep-equal ticks and inactive-workspace changes.

Shipped in `v0.13.2`: **agent-browser sessions are reaped during the app's lifetime instead of only on restart** (issue #126). Agent-browser daemons (headless Chromium behind each `AgentBrowserSession`) previously only got torn down by the restart-time PID-file reconciliation, so a long-running app session leaked one Chromium process per closed workspace that had ever opened a browser. `AppStateStore::close_workspace` now returns `CloseWorkspaceResult.removed_agent_browser_sessions` (collected under the same lock that removes the workspace, so no TOCTOU race), and a shared `reap_agent_browser_sessions` helper in `commands/workspace.rs` fire-and-forgets `AgentBrowserManager::close()` for each on BOTH close paths — `close_workspace` and `close_workspace_with_worktree_impl` (the worktree/MCP `workspace_close` path had zero agent-browser teardown before this). A new 5-minute backstop sweep in `lib.rs` closes any tracked `ws-*` session whose owning workspace no longer exists, via the pure `agent_browser::orphaned_ws_sessions` helper and `AppStateStore::live_agent_browser_session_names` — in-memory-keys-only (never shells out to `agent-browser session list`, so it can't touch another codemux instance's daemon) and `ws-*`-scoped (never touches user browser-pane sessions). See `docs/features/browser.md` § "Session reaping during app lifetime (issue #126)".

Shipped in `v0.12.0` (PR #136): **Agent Chat follow-up message queueing.** Sending a chat message while the agent is mid-turn no longer errors and orphans the bubble — the message is **queued** (backend-authoritative, in Rust session state) and auto-dispatched as the next turn when the current one completes, is interrupted, or is aborted; multiple queued messages dispatch FIFO. Queued messages render greyed-out with a "Queued" pill and an on-hover X that cancels and restores the text to the composer. New provider runtime events `TurnQueued` / `QueuedTurnDispatched` / `QueuedTurnCancelled` (`agent_provider/events.rs`), a `queued_turns: VecDeque` + `enqueue_or_send`/`drain_queue`/`cancel_queued` on the Claude and Codex session state, a `queued_id` on `TurnStartResult`, a `client_nonce` on `SendTurnInput` (race-free reconciliation of the optimistic bubble), and a new `agent_chat_cancel_queued_turn` Tauri command. The queued user-message envelope is persisted only when the turn actually DISPATCHES (`forward_event`), so chat history reflects real turn order. The Composer now allows Enter-to-queue while streaming (blocked only during the send RPC) with a subtle "Enter to queue" hint; the send path defers/rolls back cleanly so the pre-existing orphan-bubble-on-error bug is fixed. OpenCode has no queue (unchanged; `cancel_queued_turn` is a trait-default no-op). The dev mock (`src/dev/tauri-mock.ts`) simulates the full queue lifecycle. Out of scope (TODO): steering / inject-into-live-turn (Cmd+Enter "send now"), queue persistence across app restart, OpenCode parity. Verified with `cargo test` (new Claude/Codex queue tests: enqueue-while-busy, FIFO drain, cancel, close-cancels-all), `npm run check`, `npm run test` (new reducer tests for the three events), and browser-pane QA of the queued/cancel/hint states on the seeded `agent-chat-demo` mock. Shipped in `v0.9.3`: a **hard-timeout guard on every agent-browser external call** (issue #96). `run_agent_browser_native()` and the `sh -c` fallbacks in `agent_browser.rs` used `std::process::Command::output()`, which blocks indefinitely — so from the async `close()` / `start_stream()` / automation paths a wedged `agent-browser` invocation could hang the calling task forever and stall the executor (the same failure mode that hung `cargo test` to the 30-minute job timeout on the Windows CI image — the unit tests were made hermetic in `420d66f`, but the production path was still unguarded). Every CLI/process-control invocation now runs through new timeout wrappers — `output_capture_with_timeout` (captures stdout+stderr, drains pipes on background threads) and `launch_status_with_timeout` (daemon-launch form: stdout `/dev/null`, caller-set stderr log preserved) — built on `wait_with_timeout` + `kill_timed_out_child`, which on overrun SIGKILLs the child **and, on Unix, its whole process group** (`process_group(0)` so a wedged `sh -c '<bin> … && <bin> wait …'` doesn't orphan the real CLI; `child.kill()` backstop on Windows). Per-action ceilings via `action_timeout`: ~5s process control, ~10s `close`, ~30s DOM actions, ~60s `open`/`wait`. The async callers (`spawn`, `run_command`, `get_screenshot`, `close`, `start_stream`) additionally push the blocking work onto `tokio::task::spawn_blocking` so a slow CLI can't tie up a runtime worker thread. Verified by hermetic unit tests that drive the wrappers with OS built-ins (`sh`/`sleep`, `cmd`/`ping`) and assert a 30s sleeper is killed in <5s with `ErrorKind::TimedOut`, plus a process-group test proving the grandchild `sleep` is reaped — and full `npm run verify` (cargo check/test, tsc, 1942 vitest). See `docs/features/browser.md` § "hang-proof external calls".

The same work added a **`worktree_create` tool to the headless daemon catalog (now 12 tools, up from 11)** so an agent on a host can make a canonical-layout worktree directly instead of improvising one. See `docs/archive/remote-workspace-pull-fix.md`. The terminal gained **PTY output flow-control / backpressure** plumbing (a daemon-side `SetFlowPaused` request + HIGH/LOW write-queue watermarks) — inert on the live render path at the time, later wired live by issue #73 (see "Workspace & terminals" below) — plus split panes now inherit the workspace cwd, and the **standalone "Diff Viewer" new-tab (+) and command-palette entry points were removed** (the Changes-panel file-click flow is the only way to open a diff tab; the diff tab kind and all diff infrastructure stay).

`v0.7.4` shipped **first-class project identity + `main`/`worktree` workspace kind** (landed on `main` before the tag). "Project" was previously implicit (path-derived `basename(project_root)`, with `main`-vs-`worktree` inferred from `worktree_path == null`), so a repo cloned at different paths on different devices/hosts had no stable identity and agent-/host-created workspaces appeared anonymous. A new `src-tauri/src/project_identity.rs` computes identity **deterministically** — `project_uid = UUIDv5(canonical git remote ?? absolute project_root)` — so every checkout of the same remote converges on the same uid with zero coordination (no replicated projects table). `derive_kind` classifies `main` (`.git` is a directory) vs `worktree` (`.git` is a file). The headless daemon (`remote/workspace.rs`) stamps `project_uid`/`project_name`/`kind`/`repo_remote` at create plus an idempotent boot sweep; the `hosts_inventory` poller threads them into `workspaces_sync` (and finally populates `project_remote` for remote-discovered rows, closing a v1 gap); the desktop stamps `WorkspaceSnapshot.project_uid`/`workspace_kind` in `set_workspace_project_root`; and the cloud `codemux_workspaces` schema now round-trips all three fields (server-authoritative on pull). The overview groups by `project_uid` and renders a `main`/`worktree` badge, and the pull-conflict guard matches on exact `project_uid`. See `docs/archive/project-identity.md`, `docs/features/workspaces-sync.md`, `docs/features/workspaces-overview.md`.

The headline addition in `v0.7.x` is **asymmetric workspace auto-publish from `codemux-remote` hosts**: a workspace an agent creates directly on a host — via the MCP `workspace_create` tool or a manual `codemux-remote workspace register` — now surfaces in every dev device's Workspaces overview without an explicit push from the laptop. The model is deliberately asymmetric: dev devices keep their existing manual push/pull (preserves the "close laptop, continue in cloud" flow and user agency over what leaves the device); `codemux-remote` hosts auto-publish because they're always-on and exist to be used as hosts. Pipeline: a new `codemux-remote workspace list` CLI subcommand reads the daemon's SQLite directly (works even when the daemon isn't running); a new `hosts_inventory.rs` background poller runs every 60 s on each dev device, SSHes the CLI, and reconciles the result into `workspaces_sync` as sibling-only rows keyed by `(host_server_id, origin_uid)`; the existing 30 s push tick then uploads dirty rows to the cloud, so other devices see new host-side workspaces within ~90 s. Schema is additive (`ALTER TABLE workspaces_sync ADD COLUMN origin_uid TEXT`). A pull-conflict guard (`AdoptionPreview.same_branch_project_exists_at` + `SameBranchProjectBlock` dialog variant) refuses to clobber a local workspace already on the same branch of the same project.

`v0.7.x` also lands three UX fixes: configured-host buckets stay visible in the Workspaces overview even when empty (a device the user has set up shows up immediately, not only after the first workspace lands on it); close-workspace paths reconcile + push the sync row immediately so the overview never briefly mis-tags a just-closed workspace as "lives on another device"; and `ssh::probe` falls back to `~/.local/bin/codemux-remote` when the PATH lookup fails (non-interactive SSH on Arch/Ubuntu/Fedora doesn't source `~/.profile`).

The earlier `v0.6.2` headline — **MCP-on-remote** — remains daily-drivable: `codemux-remote` graduated from a slim PTY-daemon binary into a full **headless Codemux daemon** that owns its own workspace registry, axum HTTP control endpoint with bearer-token auth, and a stdio MCP server (an 11-tool catalog at `v0.6.2`; `worktree_create` added in `v0.7.5` brings it to 12). An agent CLI on a remote host (VPS, home server, anywhere `codemux-remote` is installed) can drive Codemux through MCP — `workspace_create`, `terminal_write`, `app_status` — without any UI. The desktop's push flow auto-provisions the systemd user unit, writes a per-workspace `.mcp.json`, auto-registers `codemux-remote mcp` into every supported agent config (`~/.claude.json`, `~/.codex/config.toml`, `~/.cursor/mcp.json`, …) on `serve` startup, and registers the pushed workspace into the daemon's registry — so the user clicks "Push workspace to host" once and the agent on the host sees Codemux as an MCP server with no further config. The `hosts_upgrade` background poller silently re-bootstraps every registered host when the bundled `codemux-remote` binary version differs from the host's installed version. Binary upload uses a `ssh-cat` pipeline (instead of `scp`) to work around an OpenSSH 9+ tilde-expansion bug.
