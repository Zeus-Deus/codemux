## Notes

Shipped in `v0.16.0` (2026-08-02) — sixteen merged PRs (#222–#238), grouped by subsystem below:

- **Agent Chat GUI promoted to the default interface** (PR #232). The Step 13 "Beta Features" opt-in is retired: `enable_agent_chat` + `enable_lazy_workspace_creation` now default **on** (serde defaults + `default_snapshot()` literals), and a one-time `agent_chat_promoted` marker (`promote_agent_chat_default`) upgrades existing installs — necessary because pre-promotion files carry an explicit `false` from the old default, indistinguishable from an opt-out. The marker is a standalone sentinel file (`<data root>/agent_chat_promoted`) rather than only a snapshot key, so a downgrade → upgrade round trip (an older binary rewrites `observability.json` without fields it doesn't know) can't erase it and force-revert an opt-out; the snapshot field is still read for back-compat. Opt-outs made after the promotion are respected forever. The frontend store (`feature-flags.ts`) also boots with both flags **on** pre-refresh and falls back to on if `get_feature_flags` rejects, so no legacy-chrome flash or CLI-stranding. The Settings section moved from a top-level warning-tinted "BETA FEATURES" group to **Personal → Interface** (`interface-section.tsx`, renamed from `beta-features-section.tsx`; section id `beta_features` → `interface`), with neutral styling, no Beta badge, and copy explaining the way back to the classic terminal-first (CLI) view; the Tauri command was renamed `set_agent_chat_beta` → `set_agent_chat_enabled`, and `DisabledFeaturePlaceholder` now deep-links to Settings → Interface. Quit-to-apply behavior unchanged. CLI agents remain launchable from the GUI (`+` launcher: plain click = new tab, Shift-click = split).

- **GUI responsiveness program** — all seven phases of the 2026-07-31 responsiveness audit, landed as one program (plan + what is still owed at `docs/plans/gui-responsiveness.md`). The audit's verdict was that the backend is not the frame: the long poles were unbounded renderer work, replay-from-origin chat hydration, synchronous terminal lifecycle work, and periodic jobs colliding with clicks. Four user-visible changes. **Selection paints immediately** — every activation surface routes through one `activateWorkspaceInteraction` helper that writes a pending active id synchronously and invokes Rust *after*, with an id-scoped rollback and a 5 s backstop, so the highlight no longer waits on the snapshot build, the IPC hop, and the 16 ms emit coalescer (`cycle_workspace` reached parity with `activate_workspace` on the way — it had been spawning PTYs on the IPC thread, skipping the git refresh, and never persisting the active workspace). **Chat resumes by cursor, not from event zero** — a durable `agent_chat_messages` row id (`lastPersistedEventId`) drives an `agent_chat_list_messages_after` tail read, ordered behind the channel attach with a held/filtered-release live stream, so a warm unchanged revisit reduces nothing and the old double replay is gone; tool results over 32 KiB hydrate as a stub (preview + line count) whose body is fetched on expand, never for image-bearing results; warm slices are evicted on a byte-weighted LRU exempting mounted, busy and drafted threads. **The renderer stops re-entering itself** — field-level pane subscriptions (a draft keystroke renders zero timeline rows, asserted in a test), rAF-batched `content_delta` with every other event kind flushing synchronously in arrival order, memoized transcript shells, and 1 Hz elapsed labels written imperatively via `TickingText`. **Terminal teardown moves after the incoming paint** — at most two parked serialize/dispose jobs, flushed before a same-session remount, WebGL contexts still bounded. Underneath, the backend stopped emitting on unchanged state: a change-gated `jobs.rs` git sweep (active workspace every 5 s tick, the rest on a 6-tick stride, per-cwd dedupe, blocking-pool gathers), `git fetch` capped at 2 concurrent with `kill_on_drop`, hidden-window-gated port polling, a cheap `get_resource_metrics` summary while the monitor is closed, ~10 mutate-without-emit sites converted to change-gated emitters, and three high-frequency domains moved onto ordered `app-state-delta` messages (`workspace_git` / `detected_ports` / `pane_status`) sharing one lock-stamped revision counter with the full snapshot — so one workspace's git result re-renders one sidebar card instead of the whole list. A jittered 60–70 s `app-state-revision` heartbeat plus frontend gap detection (100 ms reorder buffer, buffer-during-resync, contiguous replay, single-flight resync) restores consistency when a message is lost, which matters most on web-remote, where the new events reach browsers through the generic event hub with no registration. Measurement is first-class rather than an afterthought: `src/lib/perf/interaction-trace.ts` attributes a switch across seven phases to a double-rAF paint with p50/p95/max and a privacy-safe diagnostics export, `[codemux::perf::*]` tags time the backend sections, and `src/dev/stress-fixture.ts` scales the dev seed to the audited profile (80 workspaces, 5,000 events, ~15 MB). **What is not done: the measurement itself.** The stress matrix on Linux WebKitGTK plus one non-Linux platform, against the plan's budgets, is the outstanding exit gate for every phase, and React Compiler was deliberately documented as a follow-up rather than trialled. See `docs/features/agent-chat.md`, `docs/features/sidebar.md`, `docs/features/terminal.md`, `docs/features/observability.md`.
- **Command palette rework** (PR #230, from the `Command Palette.dc.html` design handoff). Ctrl+K stopped being an action menu with a workspace list bolted on top and became the app's **unified switcher**: one query now searches **Workspaces / Projects / Commands** together, each group a sticky header with an honest match count (`8 of 77` when capped, never a silently truncated number). The palette owns its own filtering (`shouldFilter={false}`) so the rules are the app's: scored fuzzy matching through the shared `@/lib/fuzzy`, **`/` switches to path mode** (names vs. locations — one haystack per candidate, because subsequence-matching a long path matches everything and the list stops narrowing) and **`>` switches to command mode** (workspaces/projects hidden, a `Commands` chip in the input row). The resting list answers "where was I?" rather than listing an index: needs-you > working > review > idle, then recency, with settled/snoozed work last. Rows carry the real sidebar vocabulary — project avatars from the shared appearance store, status dot + label from new shared `pane-status` maps (`STATUS_LABEL`/`STATUS_TEXT_CLASS`/`STATUS_DOT_CLASS`/`statusRank`), idle age from `formatElapsed` — plus per-row keybind hints that swap for a `↵` badge on selection, a footer hint bar, and an empty state that names the failed query. Commands became data (`{label, icon, keywords?, actionId?, run?, requiresWorkspace?}`) routed through the **same `dispatch()` the global keyboard handler uses**, so a shortcut and its palette row can't drift apart; that also picked up six actions the palette never exposed (New agent, New workspace in this project, Open project…, Next workspace, Previous workspace, Keyboard shortcuts) and a hint for Split pane down, which had a row but no shortcut shown, and workspace-scoped rows are now hidden rather than shown as silent no-ops. Selecting a project scopes the sidebar filter to it and lands on its top-ranked workspace. Extracted for reuse: `src/lib/shorten-path.ts` (was a private copy in the workspace hover card), the status label/tone/dot maps (the hover card's `STATUS_TONE` and the rail's `dotClass` now consume them), and a `.thin-scrollbar` utility in `globals.css`. One pre-existing bug fixed along the way: `sidebarToggleFn` only ever drove the desktop `open` prop, so **Ctrl+B and the palette's "Toggle sidebar" were silent no-ops below 768px** (the narrow-viewport Sheet has its own `openMobile` state) — a `SidebarToggleBridge` inside `SidebarProvider` now publishes the provider's real `toggleSidebar`. The pure query/rank/label model lives in `command-palette-model.ts` with 23 unit tests. Frontend + docs only; no Rust changes. Verified with `npm run check`, `npm run test` (3435), and a dev-mock browser drive of resting/`>`/search/path/empty states and workspace activation. See `docs/features/command-palette.md`.
- **Agent Tasks panel** (PR #229). Provider-authored plans are normalized into a durable `ProviderRuntimeEvent::TasksUpdated { thread_id, tasks }` snapshot and rendered read-only — agent state to inspect, not a second editable task list. Claude maps legacy `TodoWrite` plus the current `TaskCreate`/`TaskUpdate`/`TaskList` result stream, Codex maps `turn/plan/updated`, OpenCode maps `todo.updated`; child/subagent plans stay child-scoped and never replace the orchestrator's. `useActiveChatTasks` reads only the focused leaf pane's thread, so switching panes switches the task source. A compact `Tasks N/M` composer control and a right-panel Tasks tab appear only once a non-empty plan exists, both carrying run state (amber + spinner while a step is in flight, green check at completion). See `docs/features/agent-chat.md` § "Agent Tasks panel".
- **Context-window meter** (PR #231). The Agent Chat composer gained a donut-ring indicator beside the Send button showing the thread's live context-window occupancy, with a click popover: `{pct}% · {used}/{max}` readout, progress bar, lifetime "Total processed" line, and an auto-compaction note; ring + bar flip to the danger token above 90%. Backend-first: all three providers now emit a persisted `ProviderRuntimeEvent::ContextUsageUpdated` (Claude from assistant usage / turn-end `modelUsage` / `compact_boundary`; Codex from the app-server's `thread/tokenUsage/updated`; OpenCode from the assistant `tokens` block with the harvested catalogue window), normalized by a shared `ContextUsageTracker` (clamp used≤max, monotonic lifetime total, no-op suppression, and a sticky window that only an explicit `clear_max_tokens` drops — OpenCode's `set_model` calls it so a swap can't keep dividing by the previous model's window). The capability registry carries numeric first-paint seeds (`ContextWindowOption.context_window_tokens`, `ChatModelInfo.max_context_tokens`); hydrate-replay restores the meter after restart with no schema migration. See `docs/features/agent-chat.md` § "Context-window meter (composer)".
- **Web-remote transport bandwidth** (PR #224, issue #215). The remote transport stops paying for uncompressed traffic and JSON-encoded PTY bytes, losslessly and backwards-compatibly in both version directions. Four layers: (1) `attach_pty_output`'s channel bodies — previously Tauri-serialized JSON number arrays at ~3.4x the payload — are re-encoded in the web dispatcher onto the existing `[0x01][u32 cb][u64 idx][payload]` binary frame (JSON `chan` fallback for non-byte-array bodies; desktop in-process delivery untouched); (2) negotiated application-level WS compression (tungstenite has no permessage-deflate): a client offers `?compress=deflate` on `/ws`, the server then wraps outbound frames ≥64 B as `[0x02][u32 BE raw_len][deflate-raw]` (text) / `[0x03]` (binary) through **one shared raw-deflate stream per connection** (context takeover, sync-flush per message, skip-before-compress keeps the dictionaries in lockstep), and the client inflates synchronously via fflate — a malformed envelope poisons the stream and closes the socket so the normal reconnect path resets both sides, and declared inflate lengths are capped at 64 MiB before allocation; (3) HTTP gzip via a `tower-http` `CompressionLayer` on the JSON APIs + embedded bundle (images/predicate-excluded types never re-compressed, `/ws` + browser-pane proxy outside the layer); (4) opt-in per-connection byte counters (`CODEMUX_WEB_REMOTE_STATS=1`, logged on close). Measured live: compressed frames at ~21% of payload bytes on a real paired-browser session; the JS bundle 6.86 MB → 1.50 MB over HTTP. A committed golden fixture pins the flate2-deflate ↔ fflate-inflate pair; `src-tauri/tests/serve_web_remote_bandwidth.rs` proves negotiation, byte-exact round-trips, PTY framing/ordering on a real wire, and the gzip/`Vary`/identity matrix. Iroh wire behavior unchanged (codec kinds 2/3 reserved); browser screencast (separate proxy socket, external daemon protocol) explicitly out of scope. See `docs/features/web-remote-access.md` § "WS protocol contract".
- **One-command remote bootstrap** (PR #222). `scripts/install.sh` plus `codemux login` / `codemux connect` provide the fresh-Linux-host path: distro-aware install, headless sign-in, relay configuration, and a persistent `codemux.service` user unit. The network-free installer suite and Docker-backed Ubuntu/Fedora harness live under `scripts/install-sh.test.sh` and `scripts/e2e/remote-bootstrap/`. The client code is landed; publishing `get.codemux.org`, the account device registry, and `app.codemux.org` remains a gated human deployment. See `docs/features/web-remote-access.md` § "One-command bootstrap" and `docs/plans/one-command-remote-bootstrap.md`.
- **Workspace/chat scale and presentation follow-ups** (PRs #223/#225/#226/#227/#228). Every workspace-creation path now supplies a real title, chat surfaces share one column contract, typography rendering is tightened, background workspace cards recede unless they need attention, and the transcript uses bounded-DOM LegendList virtualization so long histories do not mount every row. These changes are documented in `docs/features/workspace-creation.md`, `docs/features/agent-chat.md`, and `docs/features/sidebar.md`.
- **Chat rendering + PR-badge follow-ups** (PRs #234/#236/#237/#238). Four late-`v0.16.0` batches whose detail is folded into the cluster bullets they extend, listed here so the release split stays honest. **#236 file-aware code blocks**: a fenced block carries its filename/path, and `chat.code_wrap` now supplies each card's `data-wrap` default instead of a root-level attribute (highlighting is stale-while-highlighting, filename sniffing tightened, the meta plugin reused). **#237 rich external links**: chat links render with favicon + readable label, streaming-safe, behind a private-host guard, with IPv4-mapped-IPv6 and astral-label-start handling. **#234 PR badge**: fork-owner filtering, the pill preserved on detached HEAD, and the write/clear/preserve decision matrix extracted to `github::branch_pr_outcome` so the 5 s sweep, the 60 s PR poll and the on-demand refresh cannot drift apart; the poll loops log a repeated `gh` failure once rather than every tick. **#238** broadened a composer-rail ancestor guard (test-only).
