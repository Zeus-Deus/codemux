Project file cache review verification
Recorded: 2026-10-17T20:12:12+00:00
Scope: src-tauri/src/commands/project_files.rs only.

Finding and fix
Concurrent requests for a cold or expired folder could each perform a complete
filesystem walk after the first audit refactor released the global cache lock.
The review fix uses one OnceLock<Arc<CacheEntry>> per folder generation. Folder
selection and expired-generation replacement happen under the global map mutex;
initialization waits and filesystem walking happen after releasing that mutex.
Inactive expired slots are pruned; active initializations and old Arc readers
remain valid. No independent lock map is retained.

Test method
A temporary rustc test harness imports the actual repository module with #[path].
It uses the real Cargo-built tauri, serde, tempfile, tokio, regex, ignore, and
nucleo_matcher dependencies. No production module is copied or stubbed.
The scanner injection calls the actual walk_project function while counting
calls. A channel pauses the first scanner, a second caller requests the same
folder, and an unrelated cold folder must finish before the paused walk is
released. Assertions require exactly one counted walk, one shared result Arc,
fresh contents, and a subsequent shared cache hit. A separate lifecycle test
checks expired-slot eviction and preservation of existing snapshot readers.
