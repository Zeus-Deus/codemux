## Roadmap At A Glance

1. Foundations landed in meaningful form: phases 0 through 9.6 established the workspace shell, multi-session terminals, pane management, notifications, browser prototype, CLI and socket control, indexing, and project memory.
2. Steps 6 through 13 (cross-cutting agent-chat work) landed on `feature/agent-chat` and merged to `main` behind the Step 13 Beta Features toggle. The full chat stack — Claude / Codex / OpenCode providers, attachments, slash commands, skills sync, MCP host runtime — ships in every release since `v0.2.0` but is OFF by default. Users opt in via Settings → Beta Features.
3. Current focus: phases 10 through 15 (OpenFlow hardening + Linux/Windows release polish), plus moving the agent-chat surface from opt-in Beta to default-on.
4. Parallel track: Phase 18 (Windows support) is **shipping** in every release. Foundation merged in `cc9b946` and shipped in `v0.1.20`/`v0.1.21`; the hardening pass (PowerShell as default shell, portable-pty fork, scrollback flush backstop, editor detection rewrite, window controls, system-process port filtering, agent-browser argv + Chromium auto-detect, control-pipe retry, Tier-3 SendInput) is on `main` and shipping. OpenFlow-on-Windows and Authenticode signing remain gated before a polished Windows v1.
5. Later: Phase 17 (macOS) has not been started.

## Recently Completed

- **Cross-device pull/adopt/close hardening (landed on `main` after the `v0.7.6` tag — unreleased).** Two audits (a deep code audit + a live SSH round-trip against a loopback host) of the remote-host push/pull/adopt + inventory-poll pipeline surfaced a cluster of failure-mode/lifecycle bugs, all off the happy path. Fixes: `workspaces_adopt_synced` checks `pull_outcome.ok` and reverts to a re-pullable sibling on failure (`unlink_workspace_sync_from_local`) instead of leaving a broken linked shell; both close paths tear down the SSH tunnel supervisor + cached client (`forget_workspace_client`/`shutdown_supervisor`) so a pushed workspace stops leaking the tunnel + remote daemon on close; all three adopt paths stamp `project_uid` (`set_workspace_project_identity`) so adopted workspaces converge with siblings instead of wiping the daemon-derived uid; the inventory poller undeletes a remote-discovered tombstone on reappear + dedupes duplicate ids in one envelope (no more cloud-row churn); `pull_workspace_back` classifies a missing remote dir as `RemoteNotFound` via a `CMX_REMOTE_DIR_OK/MISSING` stdout sentinel (was a fragile `exit status: 7` match); `provision_workspace_mcp_config` resolves the remote `$HOME` → absolute `.mcp.json` command path (the systemd `%h` specifier broke remote MCP auto-discovery); shell-injection hardening on `ssh_upload_executable`/`ssh_write_file` via tilde-aware `shell_escape`; tunnel-socket hash widened 12→16 hex chars; a stale-link pull guard (`detect_same_branch_project_conflict` intersects against live workspace ids so a closed-but-stale sync row stops phantom-blocking Pull); and a sidebar fix so the workspace-row X button no longer overlays/swallows clicks on the linked-issue badge. New env-gated (`CODEMUX_E2E_SSH_HOST`) integration harness `src-tauri/tests/codemux_ssh_roundtrip.rs` + regression unit tests. Touches `src-tauri/src/{commands/workspace.rs,commands/workspaces_sync.rs,database.rs,hosts_inventory.rs,workspaces_sync.rs,state/state_impl.rs,ssh/{push,bootstrap,registry}.rs}` + `src/components/layout/sidebar-workspace-row.tsx`. Feature docs: `docs/features/workspaces-sync.md`, `docs/features/remote-hosts.md`.
- **Agent-created host-workspace pull/adoption fix + terminal hardening (`v0.7.5`).** A workspace an agent built directly on a `codemux-remote` host (e.g. `git worktree add` + `workspace_create`) previously pulled to the desktop as an empty worktree — the pull rsynced from the conventional `~/.codemux/worktrees/<project>/<branch>` path instead of the workspace's real on-host `path`. Fixes: a new local-only `origin_path` column on `workspaces_sync` (additive ALTER) carries the daemon's real path so `workspace_pull_back_impl` rsyncs from the right place; worktree-kind adoption delegates to `adopt_worktree_via_repo_rsync` (whole-repo rsync + `git worktree prune`/`add`) to rebuild the cross-machine-broken `.git` gitfile locally and works for local-only repos; `upsert_workspace_sync_from_server` uses `COALESCE(server, local)` for `project_uid`/`workspace_kind` so a null cloud value never clobbers a locally-derived identity. The same work added a **`worktree_create` tool to the headless daemon catalog (11 → 12 tools)** + `src-tauri/src/remote/git.rs`. Terminal side: **PTY output flow-control / backpressure** plumbing (daemon `SetFlowPaused` + HIGH/LOW watermarks — landed but inert on the live render path), split panes inherit the workspace cwd, the workspace-switch freeze fix (throttled xterm write pump), and removal of the redundant standalone "Diff Viewer" new-tab (+) / command-palette entry points. Plan: `docs/plans/remote-workspace-pull-fix.md`. Feature docs: `docs/features/workspaces-sync.md`, `docs/features/remote-hosts.md`, `docs/features/terminal.md`, `docs/features/diff-viewer.md`.
- **First-class project identity + `main`/`worktree` kind (shipped in `v0.7.4` — Superset-adapted).** Replaced the implicit, path-derived "project" concept with a stable deterministic identity: `project_uid = UUIDv5(canonical git remote ?? absolute project_root)`, computed in a new `src-tauri/src/project_identity.rs` (also `derive_kind` for `main` vs `worktree` from `.git` dir-vs-file). The key deviation from Superset is determinism — every checkout of the same remote converges on the same uid with zero coordination, so no replicated projects table or reconcile step is needed. Phase 1 (daemon registry columns + idempotent ALTER migration + create-time stamp + boot sweep, host-inventory poller threading, local `workspaces_sync` columns, overview grouping + kind badge, conflict guard) and Phase 2 (desktop `WorkspaceSnapshot.project_uid`/`workspace_kind` stamped in `set_workspace_project_root`; cloud `codemux_workspaces` round-trip deployed + verified on the VPS — 303 server tests, 44 prod rows untouched) are both complete. Phase 3 (a first-class `projects` table for project-level metadata) is optional/future. Touches `src-tauri/src/{project_identity.rs,remote/workspace.rs,bin/codemux_remote.rs,hosts_inventory.rs,database.rs,workspaces_sync.rs,commands/workspaces_sync.rs}` + `src/tauri/commands.ts` + `src/components/workspaces-overview/*`. Plan: `docs/plans/project-identity.md`. Feature docs: `docs/features/workspaces-sync.md`, `docs/features/workspaces-overview.md`.
- **Asymmetric workspace auto-publish from `codemux-remote` hosts (`v0.7.x`).** A workspace an agent creates directly on a host (via the MCP `workspace_create` tool or a manual `codemux-remote workspace register`) now surfaces in every dev device's Workspaces overview without an explicit push from the laptop. New `codemux-remote workspace list` CLI subcommand reads the daemon's SQLite directly (no running daemon required); new `hosts_inventory.rs` background poller runs every ~60 s on each dev device, SSHes the CLI, and reconciles into `workspaces_sync` as sibling-only rows keyed by `(host_server_id, origin_uid)`; the existing 30 s push tick uploads them to the cloud, so other devices see new host-side workspaces within ~90 s. Pull-conflict guard via `AdoptionPreview.same_branch_project_exists_at` + `SameBranchProjectBlock` dialog variant refuses to clobber a local workspace already on the same branch of the same project. The asymmetry is deliberate — dev devices keep manual push/pull (user agency over what leaves the device), hosts auto-publish (always-on, exist to be used as hosts). Touches: `src-tauri/src/bin/codemux_remote.rs` (CLI), `src-tauri/src/hosts_inventory.rs` (poller), `src-tauri/src/database.rs` (additive column + 5 helpers), `src-tauri/src/commands/workspaces_sync.rs` (conflict detection), `src/components/workspaces-overview/pull-to-device-dialog.tsx` (`SameBranchProjectBlock` variant). 33 new unit tests + 3 integration tests.
