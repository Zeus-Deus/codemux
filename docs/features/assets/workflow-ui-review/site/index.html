CodeMux workflow UI — four directions

Mockups for review — no design integrated Verification notes

Four ways to arrange the Workflows pane, each showing the same synthetic run: Refactor session recovery in a fictional project. The run shown is an illustrative run that already opted in to file changes; a new draft starts with them off. It has one coordinator, four dynamic children, a repaired failure, a synthesis step and a two-worker ceiling. Each direction organizes the pane around a different primary unit — a decision, an attempt, a task, an event — inside the unchanged sidebar, chat and pane deck.

All states and numbers are illustrative. Interacting with these mockups calls no models, nothing is connected to a backend, and Apply never writes files. (Claude did use models to author them, and the verification notes record real inference from separate runtime tests.)

Recommendation

Lead with A · Checkpoints, and borrow B's slot strip as a single compact row under its run bar.

  • Most of the time you shouldn't be watching a workflow. You need to know when to step in and what you can accept, and A is the only direction that puts both at the top of the pane.
  • Its “What is verified” ledger separates checks CodeMux made from agent judgment and from what was never run. That keeps agent prose and a test plan from passing as evidence.
  • A one-line slot strip from B answers “who holds capacity”, including an Unknown attempt holding a slot, without A losing its decision-first order.
  • C works well as an optional Map view when the pane is expanded. D's turn grouping fits inside task detail as attempt history, but on its own it's weak for spotting what needs you at a glance.

The main risk with A is that a task moves between buckets as its state changes. Keep each bucket's order stable, and keep the selected task selected when it moves.
